# Property Order

[English](../../README.md) · [简体中文](README.zh-CN.md) · [繁體中文](README.zh-TW.md) · [日本語](README.ja-JP.md) · [한국어](README.ko-KR.md) · [Deutsch](README.de-DE.md) · [Français](README.fr-FR.md) · [Español](README.es-ES.md) · [Português (Brasil)](README.pt-BR.md) · [Русский](README.ru-RU.md) · [Tiếng Việt](README.vi-VN.md) · [العربية](README.ar.md)

Obsidian 속성에서 입력 후보와 목록 값을 관리하세요.

- **[속성 이름 후보](#속성-이름-후보)**: 속성을 추가할 때 `status`, `owner` 같은 이름을 고정하거나 숨기고, 그룹화하고 정렬합니다.
- **[속성 값 후보](#속성-값-후보)**: 속성별로 값 후보의 동작을 선택하고 `todo`, `doing`, `done` 같은 값을 미리 등록합니다.
- **[목록 값 순서 변경 및 이동](#목록-값-순서-변경-및-이동)**: 드래그나 명령 팔레트로 목록 항목의 순서를 바꾸거나 같은 노트의 지원되는 속성 사이로 이동합니다.

세 기능은 서로 독립적입니다. Property Order는 입력 후보와 목록 값을 관리하며, 노트의 속성 필드 자체를 재배열하지 않습니다. 데스크톱과 모바일에서 Obsidian 1.12.7 이상이 필요합니다.

## 속성 이름 후보

Obsidian 기본 **속성 추가** 후보에서 자주 쓰는 속성 이름을 더 쉽게 찾을 수 있습니다.

1. **설정 → Property Order → 속성 이름 후보**를 엽니다.
2. 자주 쓰는 이름은 상단에 고정하고, 가끔 쓰는 이름은 하단에 배치합니다. 정확한 이름이나 와일드카드 규칙으로 불필요한 이름을 숨길 수 있습니다.
3. 이름순, 최근 사용순, 노트 수 정렬을 선택합니다. **속성 유형별로 후보 묶기**를 사용하면 일반 후보를 Obsidian 유형별로 묶으며, 상단 고정 이름과 하단 배치 이름은 각 위치에 유지합니다.

예를 들어 `status`와 `owner`를 상단에 고정하고 `legacy_code`를 숨긴 뒤, 노트에서 **속성 추가**를 열어 결과를 확인하세요. 이 규칙은 Obsidian이 이미 제공하는 이름을 정리합니다. 이름을 고정해도 새 후보를 만들거나 노트의 필드를 이동하지 않습니다.

규칙을 적용하기 전의 기본 속성 이름 후보:

![사용자 지정 전의 기본 속성 이름 후보](../assets/property-order-key-suggestions-before.png)

같은 후보에서 자주 쓰는 이름을 고정하고 불필요한 이름을 숨긴 결과:

![status와 owner를 고정하고 legacy_code를 숨긴 속성 이름 후보](../assets/property-order-key-suggestions-after.png)

최근 사용순은 추가가 확인된 순서이며, 마우스를 올리거나 후보를 둘러본 것은 포함하지 않습니다. 이름순과 최근 사용순 정렬은 보관함을 스캔하지 않습니다. 노트 수 정렬은 캐시된 메타데이터를 사용해 각 속성을 포함한 Markdown 노트 수를 셉니다.

## 속성 값 후보

속성을 선택한 다음 표시할 값 후보를 설정합니다. 예를 들어 `status`의 `todo`, `done`입니다. 이 기능은 **기본적으로 꺼져 있으며** 속성 이름 후보와 독립적입니다.

1. **설정 → Property Order → 속성 값 후보**를 열고 **속성 값 후보 조정**을 켭니다.
2. 개별 규칙이 없는 속성의 기본 동작을 설정하거나, 정확히 일치하는 속성 이름에 Obsidian 순서, 이름순, 선택 횟수, 이 값을 포함한 노트 수, 후보 표시 안 함, 사용자 지정 후보를 할당합니다.
3. `status`용 후보 목록을 만들려면 **사용자 지정 후보** 규칙 카드를 추가하고 `status`를 넣은 다음, **후보 값 등록**으로 `todo`, `doing`, `done`을 추가합니다.

![속성 값을 편집할 때 표시되는 status의 등록된 후보](../assets/property-order-value-suggestions.png)

사용자 지정 후보는 상단 고정, 일반, 하단 배치로 나뉩니다. 명시적으로 등록한 값은 아직 어떤 노트에서도 사용하지 않아도 후보로 남으며, 입력한 내용에 따라 필터링됩니다. **↔ (일반 후보로 이동)**은 고정 위치를 해제하고 후보는 유지합니다. 설정에서 등록된 후보를 제거해도 노트 내용은 삭제하지 않습니다.

선택 횟수는 Obsidian이 값의 쓰기를 확인한 뒤에만 증가합니다. 노트 수는 그 값을 포함하는 Markdown 노트 수이며, 해당 값을 선택한 횟수가 아닙니다. **후보 표시 안 함**에서도 직접 입력할 수 있습니다. 후보 규칙만 변경하면 노트를 수정하지 않습니다.

## 목록 값 순서 변경 및 이동

속성 패널에서 지원되는 최상위 YAML 텍스트 목록 값의 순서를 바꾸거나, 같은 노트의 다른 목록 속성으로 값을 이동할 수 있습니다. 속성 간 드래그는 기본적으로 켜져 있으며 **속성 값 순서**에서 끌 수 있습니다.

![속성 사이에서 값 이동](../assets/property-order-cross-property-drag.gif)

- **데스크톱:** 값을 새 위치나 다른 지원되는 목록 속성으로 드래그합니다.
- **모바일:** 값을 길게 누르고 Obsidian 기본 메뉴에서 **순서 변경** 또는 **순서 변경 또는 이동**을 선택한 다음 해당 값을 드래그합니다. 메뉴를 확장할 수 없는 경우 기본 편집은 계속 사용할 수 있으며, 플러그인이 비슷한 메뉴로 대체하지 않습니다.
- **키보드:** 명령 팔레트에서 **Property Order: 속성 값 순서 변경**을 실행합니다. 원본 속성과 값을 선택한 다음 위, 아래, 1부터 시작하는 지정 위치, 맨 앞, 맨 뒤 또는 다른 속성의 끝으로 이동합니다. 기본 단축키는 지정되어 있지 않습니다. 드래그를 꺼도 명령은 사용할 수 있으며, 속성 간 드래그 설정은 포인터 드래그에만 적용됩니다.

완료된 순서 변경이나 이동은 한 번에 실행 취소할 수 있는 하나의 편집입니다. 업데이트를 시작하기 전에는 **Escape** 또는 **취소**를 선택해 노트를 그대로 둘 수 있습니다. 업데이트가 시작되면 완료를 기다린 뒤 필요할 때 편집기에서 실행 취소하세요. 드래그는 줄바꿈된 값, 오른쪽에서 왼쪽으로 쓰는 레이아웃, 지원되는 패널 가장자리의 스크롤, 스크린 리더 상태 알림을 지원합니다.

**순서를 바꾸기 전에 값 유형을 확인하세요:** 지원되는 텍스트 목록의 비텍스트 값은 문자열이 될 수 있습니다. 예를 들어 `true`는 `"true"`로, `123`은 `"123"`으로 바뀝니다. 값의 유형도 달라질 수 있으므로 숫자나 불리언 유형이 중요하다면 결과를 확인하세요.

**기본 목록 형식은 현재 형식 유지입니다.** **속성 값 순서**에서 대괄호 목록이나 한 줄에 한 항목 형식을 선택할 수 있습니다. 대괄호 형식으로 바꾸면 주석이나 빈 줄이 사라질 수 있으므로, 중요한 경우 현재 형식을 유지하세요. **순서 변경 후 목록 형식** 옆의 **형식 예시**를 펼쳐 옵션을 비교할 수 있습니다.

## 설치

### 커뮤니티 플러그인 (권장)

Obsidian에서 **설정 → 커뮤니티 플러그인 → 탐색**을 열고 **Property Order**를 검색한 뒤 **설치**하고 **활성화**합니다. [커뮤니티 플러그인 페이지](https://obsidian.md/plugins?id=property-order)를 열어도 됩니다.

### 수동 설치 및 업그레이드

[최신 릴리스](https://github.com/ZHYX91/obsidian-property-order/releases/latest)에서 `property-order-<version>.zip`을 다운로드해 `Vault/.obsidian/plugins/`에 압축을 풉니다. 압축 파일에는 `main.js`, `manifest.json`, `styles.css`가 들어 있는 `property-order/` 폴더가 있습니다. Obsidian을 다시 로드하고 커뮤니티 플러그인에서 Property Order를 활성화합니다.

수동 업그레이드 시 기존 `data.json`을 백업하고 유지하세요. `main.js`, `manifest.json`, `styles.css`만 교체합니다. 플러그인 설정 전체를 명시적으로 초기화하려는 경우에만 `data.json`을 삭제하세요.

## 설정 참고

지원되는 모든 Obsidian 버전은 같은 네 개의 탭을 사용합니다.

| 탭 | 설정 내용 |
| --- | --- |
| **일반** | 플러그인 언어와 선택적 진단 알림. **Obsidian 설정 따르기**는 일치하는 언어를 사용하며, 지원되지 않으면 영어를 사용합니다. |
| **속성 값 순서** | 같은 속성 및 속성 간 드래그, 순서 변경 후 목록 형식. 드래그를 꺼도 별도의 속성 간 드래그 설정은 유지합니다. |
| **속성 이름 후보** | 이름의 상단 고정, 하단 배치, 숨김, 이름순·최근 사용순·노트 수 정렬, 선택적 유형별 그룹화, 최근 기록 지우기와 규칙 테스트 입력란. |
| **속성 값 후보** | 직접 켜야 하는 기본 동작, 속성별 규칙, 등록된 사용자 지정 값, 선택 횟수 지우기. |

**이 설정 화면의 속성 순서**는 규칙 카드와 사용자 지정 편집기 안의 속성만 재배열합니다. 노트 필드나 속성 값 후보의 순서는 바꾸지 않습니다.

인터페이스와 README는 영어, 중국어 간체, 중국어 번체, 독일어, 프랑스어, 스페인어, 브라질 포르투갈어, 러시아어, 일본어, 한국어, 베트남어, 아랍어를 지원합니다.

## 호환성 및 제한 사항

- 값 드래그는 Obsidian이 텍스트 목록으로 표시하는 일반적인 최상위 YAML 속성 줄을 지원합니다. 문서 전체를 `{ ... }`로 감싼 매핑, 객체 목록, 중첩 목록, 여러 줄의 흐름 형식 목록, 소스 모드 줄 드래그, 파일 간 이동은 지원하지 않습니다.
- Obsidian이 해당 속성을 목록으로 인식하면 빈 값이나 단일 값도 참여할 수 있습니다. 개별 값이 명확한 일부 유형 불일치 행도 작동합니다. 모호한 혼합 값 행은 보수적으로 처리하며, 끝에 값 추가만 허용할 수 있습니다.
- 키보드 명령에는 활성 Markdown 창의 지원되는 속성 패널이 표시되어 있어야 합니다. 대화상자가 열린 동안 파일이나 값이 바뀌면 명령을 다시 여세요.
- 등록된 후보는 속성 패널에서 값을 편집할 때만 표시됩니다. 기본 후보 팝업이 없으면 입력란 옆에 표시할 수 있습니다. 편집기나 기본 후보 UI를 안전하게 식별할 수 없을 때도 일반 입력이나 기본 후보는 계속 사용할 수 있습니다.
- 값 순서를 바꿀 때는 Obsidian에 저장을 요청하기 전에 YAML을 확인합니다. 지원되지 않거나 충돌하는 내용은 그대로 둡니다. Obsidian에서 속성을 선택하거나 편집하면 노트가 바뀔 수 있지만, 후보 설정만 변경하면 바뀌지 않습니다.

## 개인정보 보호 및 보안

Property Order는 로컬에서 작동합니다. 계정이 필요 없으며 노트 내용을 업로드하거나 원격 서비스를 호출하지 않습니다. 값 순서 변경이나 이동은 관련 속성만 수정합니다.

노트 수는 캐시된 frontmatter 메타데이터를 사용하며 모든 노트의 본문을 읽지 않습니다. 최근 속성 이름 기록(최대 100개)과 확인된 값 선택 횟수는 현재 기기의 해당 보관함 로컬 저장소에 `data.json`과 별도로 저장됩니다. 동기화하지 않으며 설정에서 지울 수 있습니다. 마우스를 올리거나 후보를 둘러보기, 취소, 확인되지 않은 편집으로는 업데이트하지 않습니다.

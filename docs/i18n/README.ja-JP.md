# Property Order

[English](../../README.md) · [简体中文](README.zh-CN.md) · [繁體中文](README.zh-TW.md) · [日本語](README.ja-JP.md) · [한국어](README.ko-KR.md) · [Deutsch](README.de-DE.md) · [Français](README.fr-FR.md) · [Español](README.es-ES.md) · [Português (Brasil)](README.pt-BR.md) · [Русский](README.ru-RU.md) · [Tiếng Việt](README.vi-VN.md) · [العربية](README.ar.md)

Obsidian のプロパティで、入力候補とリスト値を管理できます。

- **[プロパティ名の候補](#プロパティ名の候補)**：プロパティを追加するときに、`status` や `owner` などの名前を固定、非表示、グループ化、並べ替えできます。
- **[プロパティ値の候補](#プロパティ値の候補)**：プロパティごとに値の候補を設定し、`todo`、`doing`、`done` などの値も登録できます。
- **[リスト値の並べ替えと移動](#リスト値の並べ替えと移動)**：ドラッグやコマンドパレットでリスト項目を並べ替えたり、同じノート内の対応するプロパティ間で移動したりできます。

これらは独立した機能です。Property Order は入力候補とリスト値を管理し、ノート内のプロパティ欄そのものは並べ替えません。デスクトップとモバイルの Obsidian 1.12.7 以降に対応します。

## プロパティ名の候補

Obsidian 標準の**プロパティを追加**の候補から、よく使う名前を見つけやすくします。

1. **設定 → Property Order → プロパティ名の候補**を開きます。
2. よく使う名前を上部に固定し、たまに使う名前を下部に配置します。不要な名前は完全一致やワイルドカードのルールで非表示にできます。
3. 名前順、最近使用した順、使用ノート数の順から選びます。**プロパティの種類ごとに候補をまとめる**を有効にすると、通常の候補を Obsidian の種類別にまとめ、上部に固定した名前と下部に配置した名前はその位置に保ちます。

たとえば `status` と `owner` を上部に固定し、`legacy_code` を非表示にします。ノートで**プロパティを追加**を開くと結果を確認できます。これらのルールは Obsidian がすでに提示する名前を整理するものです。名前を固定しても新しい候補は作成されず、ノート内の欄も移動しません。

ルール適用前の標準のプロパティ名候補：

![カスタマイズ前の標準のプロパティ名候補](../assets/property-order-key-suggestions-before.png)

同じ候補で、よく使う名前を固定し、不要な名前を非表示にした結果：

![status と owner を固定し legacy_code を非表示にしたプロパティ名候補](../assets/property-order-key-suggestions-after.png)

最近使用した順は、追加が確定した順序です。マウスを重ねたり候補を見たりするだけでは変わりません。名前順と最近使用した順では保管庫を走査しません。使用ノート数の順は、キャッシュされたメタデータから各プロパティを含む Markdown ノート数を数えます。

## プロパティ値の候補

プロパティを選んだ後に表示する値を設定します。たとえば `status` に対する `todo` や `done` です。この機能は**初期設定では無効**で、プロパティ名の候補とは独立しています。

1. **設定 → Property Order → プロパティ値の候補**を開き、**プロパティ値の候補を調整する**を有効にします。
2. 個別に設定していないプロパティの既定の動作を選ぶか、完全一致するプロパティ名に、Obsidian の順序、名前順、選択回数、この値を含むノート数、候補を表示しない、カスタム候補を割り当てます。
3. `status` 用の候補リストを作るには、**カスタム候補**のルールカードを追加し、`status` を入れ、**候補を登録**で `todo`、`doing`、`done` を追加します。

![プロパティ値の編集中に表示される status の登録済み候補](../assets/property-order-value-suggestions.png)

カスタム候補には、上部に固定する候補、通常の候補、下部に配置する候補があります。明示的に登録した値は、どのノートにもまだ使われていなくても候補に残り、入力した文字で絞り込まれます。**↔（通常の候補に戻す）**は固定位置を解除し、候補自体は残します。設定から候補を削除しても、ノートの内容は削除しません。

選択回数は、Obsidian が値の書き込みを確認してから数えます。使用ノート数は、その値を含む Markdown ノート数であり、選んだ回数ではありません。**候補を表示しない**でも手入力できます。候補のルールを変えるだけではノートを編集しません。

## リスト値の並べ替えと移動

対応するトップレベルの YAML テキストリストをプロパティ内で並べ替えたり、同じノートの別のリストプロパティに値を移動したりできます。プロパティ間のドラッグは初期設定で有効です。**値の並び順**で無効にできます。

![プロパティ間で値を移動](../assets/property-order-cross-property-drag.gif)

- **デスクトップ：**値を新しい位置や、別の対応するリストプロパティへドラッグします。
- **モバイル：**値を長押しし、Obsidian 標準メニューから**並べ替え**または**並べ替え・移動**を選んでから、その値をドラッグします。メニューを拡張できない場合は標準の編集を引き続き利用でき、プラグインは類似のメニューで置き換えません。
- **キーボード：**コマンドパレットから **Property Order: プロパティ値を並べ替え**を実行します。移動元のプロパティと値を選び、上、下、1 から始まる指定位置、先頭、末尾、または別のプロパティの末尾へ移動します。既定のショートカットはありません。ドラッグが無効でも使えます。プロパティ間のドラッグ設定はポインターによるドラッグだけに適用されます。

並べ替えや移動は、それぞれ 1 回で元に戻せる編集になります。更新を始める前なら **Escape** または**キャンセル**でノートを変更せずに終了できます。更新が始まったら完了を待ち、必要に応じてエディターで元に戻してください。ドラッグは、値の折り返し、右から左へのレイアウト、対応するパネル端でのスクロール、スクリーンリーダーへの状態通知に対応します。

**並べ替え前に値の型を確認してください：**対応するテキストリストの非テキスト値は文字列になることがあります。たとえば `true` が `"true"`、`123` が `"123"` になります。値の型も変わるため、数値型や真偽値型が必要な場合は結果を確認してください。

**リスト形式は、初期設定では現在の形式を保持します。** **値の並び順**で、角括弧のリストや 1 行 1 項目の形式を選べます。角括弧の形式に変えるとコメントや空行が失われることがあります。必要な場合は現在の形式を保持してください。**並べ替え後のリスト形式**の横にある**形式の例**を展開すると、各形式を比較できます。

## インストール

### コミュニティプラグイン（推奨）

Obsidian で**設定 → コミュニティプラグイン → 閲覧**を開き、**Property Order** を検索して**インストール**し、**有効化**します。[コミュニティプラグインのページ](https://obsidian.md/plugins?id=property-order)からも開けます。

### 手動インストールと更新

[最新リリース](https://github.com/ZHYX91/obsidian-property-order/releases/latest)から `property-order-<version>.zip` をダウンロードし、`Vault/.obsidian/plugins/` に展開します。`property-order/` ディレクトリ内に `main.js`、`manifest.json`、`styles.css` が入っています。Obsidian を再読み込みし、コミュニティプラグインで Property Order を有効にしてください。

手動更新時は、既存の `data.json` をバックアップし、そのまま保持してください。`main.js`、`manifest.json`、`styles.css` だけを置き換えます。すべてのプラグイン設定を明示的にリセットしたい場合にだけ `data.json` を削除してください。

## 設定リファレンス

対応するすべての Obsidian バージョンで、同じ 4 つのタブを使います。

| タブ | 設定内容 |
| --- | --- |
| **一般** | プラグインの言語と任意の診断通知。**Obsidian に合わせる**は対応する言語を使い、未対応なら英語になります。 |
| **値の並び順** | 同じプロパティ内とプロパティ間のドラッグ、並べ替え後のリスト形式。ドラッグを無効にしても、プロパティ間の個別設定は保持します。 |
| **プロパティ名の候補** | 名前の上部固定、下部配置、非表示、名前順・最近使用した順・使用ノート数の並べ替え、任意の種類別グループ化、履歴の消去、ルールのテスト欄。 |
| **プロパティ値の候補** | 有効化が必要な既定の動作、プロパティ別ルール、登録済み候補、選択回数の消去。 |

**この設定画面でのプロパティの並び順**は、ルールカードとカスタムエディター内のプロパティだけを並べ替えます。ノート内の欄や値候補の順序は変えません。

インターフェースと README は、英語、簡体字中国語、繁体字中国語、ドイツ語、フランス語、スペイン語、ブラジルポルトガル語、ロシア語、日本語、韓国語、ベトナム語、アラビア語に対応します。

## 互換性と制限

- 値のドラッグは、Obsidian がテキストリストとして表示する、通常のトップレベル YAML プロパティ行に対応します。文書全体を `{ ... }` で囲むマッピング、オブジェクトのリスト、入れ子のリスト、複数行のフロー形式リスト、ソースモードの行ドラッグ、ファイル間の移動には対応しません。
- Obsidian がリスト型のプロパティと認識する場合は、空の値や単一値も対象になります。個々の値を明確に識別できる型不一致の行にも対応する場合があります。曖昧な混合値の行は慎重に扱い、末尾への追加だけを許可する場合があります。
- キーボードコマンドには、アクティブな Markdown ペイン内の、表示された対応プロパティパネルが必要です。ダイアログを開いている間にファイルや値が変わった場合は、コマンドを開き直してください。
- 登録済みの候補は、プロパティパネルで値を編集中にだけ表示します。標準の候補ポップアップがない場合は、入力欄の横に表示することがあります。エディターや標準の候補 UI を安全に識別できない場合も、通常の入力や標準の候補は引き続き利用できます。
- 値を並べ替える際は、Obsidian に保存を依頼する前に YAML を検証します。非対応の内容や競合する内容は変更しません。Obsidian でプロパティを選択・編集するとノートが変わる場合がありますが、候補の設定だけでは変わりません。

## プライバシーとセキュリティ

Property Order はローカルで動作します。アカウントは不要で、ノートの内容をアップロードせず、外部サービスも呼び出しません。値の並べ替えや移動は、対象のプロパティだけを変更します。

使用ノート数にはキャッシュされた frontmatter メタデータを使い、各ノートの本文を読みません。最近使用したプロパティ名の履歴（最大 100 件）と、確定した値の選択回数は、現在の端末にある保管庫ごとのローカルストレージに `data.json` とは別に保存されます。同期されず、設定から消去できます。マウスを重ねる、候補を見る、キャンセルする、未確定の編集を行うだけでは更新しません。

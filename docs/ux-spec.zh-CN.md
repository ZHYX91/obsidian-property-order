# Property Order — 交互规范

本文描述 Property Order 的当前交互与呈现契约。英文版用于同步阅读；若翻译冲突，以本文为准。

## 属性值排序

- 不使用指针时，从命令面板打开属性值重排，选择源属性和值，再执行上移、下移或移至另一属性末尾。命令默认不绑定快捷键，关闭拖拽或跨属性拖拽时仍可使用。
- 源和目标来自当前 Markdown pane 可见、可核对的原生 Properties。提交前 Escape 或取消关闭选择而不写入；更新期间等待完成，成功或已提交但保存安排失败时关闭对话框。拒绝或失败后保留提示并禁用再次执行，需要检查笔记、关闭并重新打开命令。选择期间文件或值变化时，提示重新打开命令，不自动套用旧选择。成功操作和指针拖拽共用撤销、保存和属性面板恢复反馈。
- “重排后的列表格式”旁的前后示例使用同一个输入。展开后并列显示 `preserve`、`flow` 和 `block` 的生产重写结果，并明确提示非文本值可能成为字符串，以及 flow 格式无法保留的注释和空行。默认保持 `preserve`。

- 点击 pill 不启动拖拽；桌面鼠标超过移动阈值后启动，桌面 touch/pen 长按后启动。
- 移动端长按仍打开 Obsidian 原生属性值菜单，并追加“重排”或“重排或移动”。选择后该 pill 显示待拖动状态；下一次在同一 pill 上 touch/pen 移动即可开始拖拽，无需再次长按。
- 移动端待拖动状态只消费一次并在 15 秒后过期；点击其他位置、Escape、超时、插件卸载或 DOM 失效都会取消。只有待拖动按压才抑制默认触摸移动和重复原生菜单。
- 预览保持源 pill 的渲染尺寸和单行省略，按所属 document 的 visual viewport 缩放与限制，四周保留可见边距。
- 命中点下的可滚动祖先和发起 pane 只有在指针进入其有界边缘区域时才滚动；每个 animation frame 的步长设有上限，避免拖拽滚动失控。
- drop indicator 必须清楚表达逻辑插入槽，包括换行和 RTL inline direction；同属性 noop、非法跨属性目标和跨文件目标不得写回。
- 拖拽开始或目标变化时，向屏幕阅读器播报当前状态；启用 reduced motion 时只关闭预览和指示器动画，不改变拖拽逻辑。
- 指针位于同一 pane 内明确的非列表属性上时，隐藏 drop indicator，以警示轮廓和 `not-allowed` 光标标记目标；仅在该目标上松手时显示一次“目标不是列表属性”Notice，经过后离开不提示。
- 原生列表类型不匹配字段的值编辑区域可在超过阈值后拖动，但插件不添加常驻抓手、不挤压或覆盖宿主警告图标；警告图标本身保持原生光标且不作为拖拽起点。只有支持 hover 的精细指针在输入未聚焦时显示 `grab` / `grabbing` 光标，聚焦编辑与粗指针保持原生呈现。

- 成功写回后，可见的 Properties 必须自动与编辑器当前状态保持一致，包括稍后发生的撤销和重做；用户不应为了让界面更新而再按一次快捷键。
- 如果自动恢复失败，显示带“刷新属性面板”按钮的持久提示。按钮只刷新原 pane 的界面，不再次写值或安排保存；重试仍失败时才建议重新打开笔记。
- 插件不得自动关闭或重开笔记。
- 成功拖拽后无需先点击正文即可使用平台快捷键撤销或重做。插件只在用户尚未主动聚焦其他控件、pane 或窗口时，把宿主重建丢失的焦点恢复给原 Markdown editor；noop、取消、拒绝、冲突和未生效写入不强制改变焦点。
- 完成、取消、冲突、pointercancel、Escape、blur、文件切换或组件消失都清理预览、指示器、live-status 节点、cursor class、计时器和临时 listener。
- 内容冲突显示本地化提示并保留最新文件，不自动重试或覆盖。

## 属性键候选

- 增强复用原生菜单节点，不复制一个视觉相似的替代菜单。
- 置顶项在前、普通项居中、置底项在后，隐藏项不占可见导航顺序。
- 可选的属性类型分组只作用于普通区，依次分为文本、列表、数字、复选框、日期、日期与时间、标签、自动 / 未指定；当前名称、最近使用或笔记数模式仍只在各组内部排序。组标题只用于显示：键盘和触摸导航不会停在标题上，辅助技术也不会把标题当成一个候选项。
- “最近使用”对普通区采用严格 MRU：已确认名称按从新到旧排列，历史中没有的候选按名称排序；置顶、置底和隐藏规则的优先级不变。历史中已不存在的名称不显示，也不占位置。
- 只有属性名称成功提交并由 Metadata Cache 确认新增到当前笔记后，才更新最近使用顺序。hover、键盘浏览、取消、失败和未确认输入不得改变 MRU，因而菜单关闭前的视觉选择不等于一次使用。
- “笔记数”按包含该属性的缓存 Markdown 笔记数降序排列，平局回退到名称排序；它不是点击次数或选择次数。名称与最近使用模式不得为了排序遍历 Vault。
- 不带修饰键的上/下方向键、Home/End 和 PageUp/PageDown 按最终可见顺序切换候选；macOS/iOS 另支持 Ctrl+P/N。其他带 Shift、Alt、Meta 或 Ctrl 的导航交给属性输入框，例如 Shift+Home 仍选择文本。Enter 只激活当前可见项，全部隐藏时不提交。
- 鼠标 hover 后切回键盘时，以最新键盘动作重新建立唯一可见选择。
- Escape、焦点离开、菜单关闭、设置禁用和插件卸载保留或恢复原生关闭与输入行为。
- DOM 结构不匹配、候选文本不可读或宿主选择无法同步时，不留下部分隐藏或部分重排状态。

## 属性值候选

- 属性值候选继续独立开关并默认关闭。未单独配置的属性使用一个全局默认，可选原生、按名称、按选择次数、按笔记数或不显示候选。
- 规则卡片按需出现，包含行为选择、属性胶囊和添加输入框。修改卡片行为会迁移全部 key，同类卡片合并；在“最近加入”顺序中，整张卡片迁入的属性也排在目标组原有属性前面。局部更新保留页面位置和焦点；点击已选中的自定义 key 不重绘。
- 精确属性 key 可加入六个互斥分组之一：按名称、按选择次数、按笔记数、原生顺序、不显示候选、自定义候选。从分组移除后恢复跟随默认。
- 五个普通分组把已配置的属性显示为紧凑且可移除的胶囊。“本页属性排列”只排列这些规则卡片中的属性和自定义候选的属性列表，可选“按属性名称”或“按最近加入规则的时间”；笔记中的属性顺序和值候选顺序不受影响。
- “添加属性”既允许直接输入，也从 Vault 已发现 key 与插件当前已配置 key 的并集中自动补全。新配置的预设属性即使移出分组，仍保留在自动补全中。已经在目标分组中的 key 标记为不可重复添加；已经在其他分组中的 key 仍显示当前归属，选择后先确认，再一次性移动。
- 自定义候选并排显示属性列表与当前属性的候选编辑器：从左到右时列表在左，从右到左时列表在右；窄宽度下改为上下堆叠，不强制保留两栏。
- 自定义候选编辑器同时展示置顶、普通、置底三段。候选可在三段之间拖动；键盘可访问的移动、上移、下移按钮提供等价操作。置顶和置底还允许直接输入字面候选值。
- 编辑候选、规则或本页属性排列时，设置和界面立即更新，不必等待保存完成。保存期间仍可添加属性或切换规则卡片的行为；较早保存的完成或失败不得重新选择旧属性、清空后来输入的草稿或改变其光标位置。
- 手动配置的值成为预设候选。把它拖回普通段只取消固定位置，仍保留预设身份；“移除预设”只移除插件配置，不得删除任何笔记中的已有值。
- 普通候选可按原生、名称、选择次数或笔记数排序；置顶和置底保持用户明确指定的顺序，不受普通段排序模式影响。
- 自定义预设值即使不在 Obsidian 原生弹窗中也继续显示。存在原生弹窗时，插件自有预设项加入该弹窗；不存在原生弹窗时，在当前属性值编辑器旁显示插件自有回退弹窗。两条路径都按当前输入筛选并遵循最终可见键盘顺序。
- 选择插件自有预设值时，通过当前聚焦的原生属性值编辑器输入路径提交，绝不直接写 frontmatter。选择次数只在该属性或自定义普通区使用“按选择次数排序”，且 Metadata Cache 已确认该值真正写入后增加。
- “不显示候选”只隐藏候选，不禁用手动输入。Escape、焦点离开、关闭功能、关闭窗口或卸载插件都移除插件自有弹窗状态并恢复原生状态。
- 无法在不改变含义的情况下迁移的 schema 5 旧规则，以只读方式继续保留并生效，直到用户显式确认切换到分组模型。

## 设置页

- 常规、属性值排序、属性名候选、属性值候选是各宿主版本共用的四个设置组。控件值、条件显隐、即时生效、保存失败和重试行为保持一致。
- “界面语言”按各语言自己的名称列出 12 种语言，并提供“跟随 Obsidian”以采用宿主界面语言；单独选定的插件语言优先。README 提供相同 12 种语言的完整内容，工程文档继续提供简体中文和英文。
- 使用阿拉伯语时，只有 Property Order 的设置内容从右到左显示；切回英语或其他支持语言后恢复从左到右。左右方向键随本页方向切换页签，Home/End 仍选择第一个和最后一个页签。切换语言或关闭设置页不会改变 Obsidian 宿主设置容器、其他设置页或工作区的语言与方向。
- 自定义四页签界面提供 `tablist`、`tab`、`tabpanel`、`aria-selected` 和 roving `tabindex`；Left/Right、Home/End 切换页签，重渲染、旋转和 viewport resize 后活动页签保持可见并保留合理焦点，包括 RTL 布局中的横向滚动。
- 精细指针页签最小高度为 34px，粗指针为 44px；活动页签同时使用强调色下划线和半粗字重，标签基线与内容面板之间保留稳定间距；窄宽度下标签栏单行横向滚动，不产生纵向裁切。
- 所有受支持的 Obsidian 版本都显示相同的四个顶部设置页签。属性名规则编辑器和属性值候选分组在不同宿主版本中保持一致的建议、保存、确认和清理行为；属性在分组之间移动时，不能短暂同时出现在两个分组。
- 属性名候选提供“清除最近使用历史”。操作会取消待确认项，只清除当前 Vault、当前设备最多 100 条最近记录，并立即刷新已打开的候选菜单；不会修改 `data.json` 或笔记。如果本地记录删除失败，应明确提示“本次会话已清除，但重启后可能恢复”。
- 属性名候选提供一个不保存的规则测试框。输入属性名称后，结果区实时显示首个命中的隐藏、置顶和置底规则，并说明“隐藏 > 置顶 > 置底”的优先级；变化通过 `aria-live="polite"` 播报。清空输入后恢复提示文案，修改规则后已有测试结果立即刷新，整个测试过程不扫描 Vault。
- 宽度不超过 480px 时，属性名规则文本框与规则测试输入占满控件区；属性值分组的添加控件改为纵向排列，自定义候选的属性列表与候选编辑器折叠为单列，并保持当前选中 key。
- 开关或语言选择需要重绘页面时，在用户操作当时完成重绘；保存完成后的回调只更新保存状态，保留随后输入的草稿、光标和当前属性选择。
- 保存失败显示 Notice 和 `role="alert"` 未保存状态；“重试保存”成功后清除提示并执行所需候选刷新。

## 可访问性与已接受边界

- 所有设置控件、页签和错误状态使用可访问名称与语义。
- 键候选支持键盘导航，并保持宿主原生选择行为。
- 属性值重排提供命令面板路径，不要求先聚焦或拖动 pill。指针拖拽继续提供 `polite` live-status；键盘对话框的焦点顺序、取消和提交，以及真实读屏播报，都需要各自的宿主/辅助技术验收，不能只凭 DOM 测试推定。
- Android 发布矩阵覆盖原生菜单保留、单次待拖动流程、属性名称候选、旋转、窄屏和生命周期；物理设备的触感、pen 差异和厂商输入栈仍不属于自动证据。

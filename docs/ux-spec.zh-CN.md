# Property Order — 交互规范

本文描述 Property Order 的当前交互与呈现契约。英文版用于同步阅读；若翻译冲突，以本文为准。

## 属性值拖拽

- 点击 pill 不启动拖拽；桌面鼠标超过移动阈值后启动，桌面 touch/pen 长按后启动。
- 移动端长按仍打开 Obsidian 原生属性值菜单，并追加“重排”或“重排或移动”。选择后该 pill 显示待拖动状态；下一次在同一 pill 上 touch/pen 移动即可开始拖拽，无需再次长按。
- 移动端待拖动状态只消费一次并在 15 秒后过期；点击其他位置、Escape、超时、插件卸载或 DOM 失效都会取消。只有待拖动按压才抑制默认触摸移动和重复原生菜单。
- 预览保持源 pill 的渲染尺寸和单行省略，按所属 document 的 visual viewport 缩放与限制，四周保留可见边距。
- 命中点下的可滚动祖先和发起 pane 只有在指针进入其有界边缘区域时才滚动；每个 animation frame 的步长设有上限，避免拖拽滚动失控。
- drop indicator 必须清楚表达逻辑插入槽，包括换行和 RTL inline direction；同属性 noop、非法跨属性目标和跨文件目标不得写回。
- 拖拽开始与目标状态变化通过 polite live status 播报；reduced motion 只关闭预览和指示器过渡，不改变几何与清理语义。
- 指针位于同一 pane 内明确的非列表属性上时，隐藏 drop indicator，以警示轮廓和 `not-allowed` 光标标记目标；仅在该目标上松手时显示一次“目标不是列表属性”Notice，经过后离开不提示。
- 原生列表类型不匹配字段的值编辑区域可在超过阈值后拖动，但插件不添加常驻抓手、不挤压或覆盖宿主警告图标；警告图标本身保持原生光标且不作为拖拽起点。只有支持 hover 的精细指针在输入未聚焦时显示 `grab` / `grabbing` 光标，聚焦编辑与粗指针保持原生呈现。
- 成功写回后自动让 Properties 与当前精确撤销/重做状态对齐，包括拖拽初始对账及延迟保存窗口均结束后才执行的撤销或重做；一次快捷键必须同时更新 editor buffer 与可见 Properties，无需再按一次历史快捷键。自动恢复失败时，持久 Notice 提供“刷新属性面板”按钮。按钮每次点击都重新读取当前合法状态，只刷新原 pane 的 UI，不再次写值或安排保存；仍失败时才建议重新打开笔记，插件不得自动关闭或重开。
- 成功拖拽后无需先点击正文即可使用平台快捷键撤销或重做。插件只在用户尚未主动聚焦其他控件、pane 或窗口时，把宿主重建丢失的焦点恢复给原 Markdown editor；noop、取消、拒绝、冲突和未生效写入不强制改变焦点。
- 完成、取消、冲突、pointercancel、Escape、blur、文件切换或组件消失都清理预览、指示器、live-status 节点、cursor class、计时器和临时 listener。
- 内容冲突显示本地化提示并保留最新文件，不自动重试或覆盖。

## 属性键候选

- 增强复用原生菜单节点，不复制一个视觉相似的替代菜单。
- 置顶项在前、普通项居中、置底项在后，隐藏项不占可见导航顺序。
- “最近使用”对普通区采用严格 MRU：已确认名称按从新到旧排列，历史中没有的候选按名称排序；置顶、置底和隐藏规则的优先级不变。历史中已不存在的名称不显示，也不占位置。
- 只有属性名称成功提交并由 Metadata Cache 确认新增到当前笔记后，才更新最近使用顺序。hover、键盘浏览、取消、失败和未确认输入不得改变 MRU，因而菜单关闭前的视觉选择不等于一次使用。
- “笔记数”按包含该属性的缓存 Markdown 笔记数降序排列，平局回退到名称排序；它不是点击次数或选择次数。名称与最近使用模式不得为了排序遍历 Vault。
- 键盘选择 class 与最终可见顺序一致；Enter 只激活当前可见项，全部隐藏时不提交。
- 鼠标 hover 后切回键盘时，以最新键盘动作重新建立唯一可见选择。
- Escape、焦点离开、菜单关闭、设置禁用和插件卸载保留或恢复原生关闭与输入行为。
- DOM 结构不匹配、候选文本不可读或宿主选择无法同步时，不留下部分隐藏或部分重排状态。

## 属性值候选

- 属性值候选继续独立开关并默认关闭。未单独配置的属性使用一个全局默认，可选原生、按名称、按选择次数、按笔记数或不显示候选。
- 精确属性 key 可加入六个互斥分组之一：按名称、按选择次数、按笔记数、原生顺序、不显示候选、自定义候选。从分组移除后恢复跟随默认。
- 五个普通分组把已配置 key 显示为紧凑且可移除的胶囊；整页共用一个“按属性名称 / 按最近加入当前分组”的显示偏好。它只改变设置页胶囊顺序，不改变 YAML key 或值候选顺序。
- “添加属性”既允许直接输入，也从 Vault 已发现 key 与插件已配置 key 的并集中自动补全。已经在目标分组中的 key 标记为不可重复添加；已经在其他分组中的 key 仍显示当前归属，选择后先确认，再一次性移动。
- 自定义候选左侧为属性列表，右侧为当前属性的候选编辑器；窄宽度下改为上下堆叠，不强制保留两栏。
- 自定义候选编辑器同时展示置顶、普通、置底三段。候选可在三段之间拖动；键盘可访问的移动、上移、下移按钮提供等价操作。置顶和置底还允许直接输入字面候选值。
- 手动配置的值成为预设候选。把它拖回普通段只取消固定位置，仍保留预设身份；“移除预设”只移除插件配置，不得删除任何笔记中的已有值。
- 普通候选可按原生、名称、选择次数或笔记数排序；置顶和置底保持用户明确指定的顺序，不受普通段排序模式影响。
- 自定义预设值即使不在 Obsidian 原生弹窗中也继续显示。存在原生弹窗时，插件自有预设项加入该弹窗；不存在原生弹窗时，在当前属性值编辑器旁显示插件自有回退弹窗。两条路径都按当前输入筛选并遵循最终可见键盘顺序。
- 选择插件自有预设值时，通过当前聚焦的原生属性值编辑器输入路径提交，绝不直接写 frontmatter；只有 Metadata Cache 确认该值真正写入后才增加选择次数。
- “不显示候选”只隐藏候选，不禁用手动输入。Escape、焦点离开、关闭功能、关闭窗口或卸载插件都移除插件自有弹窗状态并恢复原生状态。
- 无法在不改变含义的情况下迁移的 schema 5 旧规则，以只读方式继续保留并生效，直到用户显式确认切换到分组模型。

## 设置页

- General、Value order、Key suggestions、Value suggestions 是跨宿主版本保持一致的四个逻辑设置组；控件值、条件显隐、即时生效、保存失败和重试语义不得因渲染路径而变化。
- Obsidian 1.12.x 使用自定义四页签界面，并提供 `tablist`、`tab`、`tabpanel`、`aria-selected` 和 roving `tabindex`；Left/Right、Home/End 切换页签，重渲染、旋转和 viewport resize 后活动页签保持可见并保留合理焦点。
- 1.12.x 的精细指针页签最小高度为 34px，粗指针为 44px；活动页签同时使用强调色下划线和半粗字重，标签基线与内容面板之间保留稳定间距；窄宽度下标签栏单行横向滚动，不产生纵向裁切。
- 所有受支持 Obsidian 版本都使用同一套 imperative 四个顶部页签。声明式设置保持关闭，因为它会绕过这套布局；属性名规则编辑器与属性值候选分组控件都保留建议、保存、确认和 cleanup 生命周期，跨属性值分组移动 key 时不得出现瞬时重复归属。
- Key suggestions 在两条渲染路径中都提供“清除最近使用历史”。操作会取消待确认项，只清除当前 Vault、当前设备在内存中的最多 100 项无时间戳 MRU，并立即刷新已打开的增强菜单；不修改 `data.json` 或笔记。成功时显示确认；local-storage 删除失败时提示本次会话已清除、但重启后可能恢复。
- Key suggestions 在两条渲染路径中都提供一个不保存的规则测试框。输入属性名称后，结果区实时列出首个命中的隐藏、置顶和置底规则，明确显示“隐藏 > 置顶 > 置底”的生效优先级，并以 `aria-live="polite"` 播报变化；清空输入恢复提示文案。规则编辑后已有测试结果立即刷新，测试过程不扫描 Vault。
- 宽度不超过 480px 时，属性名规则文本框与规则测试输入占满控件区；属性值分组的添加控件改为纵向排列，自定义候选的属性列表与候选编辑器折叠为单列，并保持当前选中 key。
- 保存失败显示 Notice 和 `role="alert"` 未保存状态；Retry 成功后清除提示并执行所需候选刷新。

## 可访问性与已接受边界

- 所有设置控件、页签和错误状态使用可访问名称与语义。
- 键候选支持键盘导航，并保持宿主原生选择行为。
- 属性值重排当前依赖指针输入；缺少键盘直接重排和拖拽 live-region 是已公开限制，不伪装成已完成能力。
- Android 发布矩阵覆盖原生菜单保留、单次待拖动流程、属性名称候选、旋转、窄屏和生命周期；物理设备的触感、pen 差异和厂商输入栈仍不属于自动证据。

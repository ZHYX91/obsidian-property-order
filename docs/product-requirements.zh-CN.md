# Property Order — 产品需求

本文描述 Property Order 的当前产品边界。英文版用于同步阅读；若实现、测试或翻译与本文冲突，以本文为准。

## 产品目标

Property Order 增强 Obsidian Properties 的三类顺序：

1. 在当前笔记的顶层 YAML 列表属性中重排值；
2. 按用户规则重排和过滤原生属性键候选；
3. 按属性规则重排和过滤原生属性值候选。

插件只修改本次操作涉及的内容，并保证成功修改可以撤销。无法识别 Obsidian 界面时保留原生行为；无法安全解析或验证 frontmatter 时不写入笔记。

## 属性值顺序

- 支持由 Obsidian Properties 渲染为 pill 的顶层 flow list 与 block list。
- 支持同属性重排；启用跨属性拖拽后，支持同一 leaf、同一文件内受支持属性之间移动。

- 是否属于可拖拽列表，以 Obsidian Properties 实际显示的属性类型为准。正常多值编辑器，以及带原生列表图标但同时显示类型不匹配警告的属性，都可以在满足安全条件时参与。
- YAML 中的空值、`[]` 或单个受支持标量，可以作为逻辑文本列表处理：标量既可以拖出，也可以接收拖入值。混合数组如果被 Obsidian 合并成一个字段，插件不得猜测具体 source 元素；只有显示内容能与当前 YAML 无歧义对应时，才允许把新值追加到末尾。
- 成功操作会把受影响属性中的非字符串值转换为文本，但保留原始 YAML 写法。例如 number、boolean 和列表内 null 会按原 token 文本转成带引号字符串；对象、嵌套结构和多行值不自动转换。
- 桌面鼠标移动达到阈值后开始拖拽；桌面应用收到的 touch/pen 输入在长按后开始拖拽。
- 移动端通过原生属性值菜单把一个 pill 置为 15 秒单次待拖动状态；下一次在同一 pill 上 touch/pen 移动达到较小阈值后直接开始拖拽，无需再次长按。点击其他位置、Escape、超时、插件卸载或 DOM 失效都会取消待拖动状态。
- drop 几何遵循容器的 inline direction，包括 RTL 布局中的换行；拖拽靠近可滚动 Properties 区域边缘时，以有上限的步长滚动适用容器。polite live region 播报拖拽开始与目标状态变化；启用 reduced motion 时关闭预览和指示器过渡动画。

- 写回格式可选 `preserve`、`flow` 或 `block`。同属性重排和跨属性移动都使用同一套规则，并且一次成功拖拽只形成一个撤销步骤。
- 只有编辑器内容与计划结果完全一致时，插件才安排保存和刷新 Properties。如果内容在提交前发生变化，操作直接取消；如果内容已经成功写入但后续保存安排失败，则保留已写入内容并提示用户手动保存。
- 写入成功后，插件应让可见的 Properties 与当前编辑器内容保持一致，并支持正常的立即撤销和重做。自动刷新失败时提供“刷新属性面板”操作；只有再次失败才建议重新打开笔记。
- 插件不得通过自动重开笔记、直接 Vault 写入、原生属性 setter、手工搬动 pill 或额外回滚来伪造成功结果。noop、取消、冲突和失败也不得顺便格式化无关内容。
- 精确提交后，同一个 Markdown editor 必须立即接管平台撤销/重做快捷键；Properties 重建或对账造成的宿主焦点丢失只能在用户没有主动把焦点移到其他控件、pane 或窗口时受守卫恢复。用户无需先点击正文即可撤销；noop、取消、拒绝、冲突或事务未生效不得强制聚焦 editor。异步对账期间 buffer 精确恢复为本次 transaction 的提交前文本属于合法的立即撤销，不得报 divergence/不同步或重放已撤销内容。
- 文件、leaf、源/目标内容或 DOM 身份在事务期间变化时取消，不得写入其他文件或覆盖较新内容。
- 拖入同一 pane 内具有原生非列表证据且由标量存储形态佐证的属性时，目标显示拒绝态且不显示插入指示器；只有在该目标上松手才显示本地化 Notice，单纯经过时不提示；无法判定的宿主属性行静默取消，不得误标为非列表。
- 冲突、非法结构或不支持结构必须给出诊断并保持磁盘内容不变。

## 属性键候选

- 支持置顶、置底、隐藏通配规则，以及按名称、最近使用和包含属性的 Markdown 笔记数排序，并可选择按 Obsidian 属性类型分组普通候选。
- 开启类型分组时，普通候选依次形成“文本、列表、数字、复选框、日期、日期与时间、标签、自动 / 未指定”八组；当前名称、最近使用或笔记数排序只在各组内部生效。隐藏仍先过滤，置顶候选位于所有类型组之前，置底候选位于所有类型组之后。组标签只呈现在已有原生候选节点上，不新增可选择的候选项。
- 名称排序依次处理数字、拉丁字母、按拼音排列的中文和其他字符；笔记数按降序排列，平局使用同一名称比较器。该计数表示缓存 frontmatter 中包含该属性的 Markdown 笔记数，不表示用户交互次数。
- 最近使用采用严格 MRU。隐藏规则先过滤；置顶规则按配置顺序优先；其余已记录属性名称按最近确认顺序从新到旧排列，未记录名称使用名称排序；置底规则最后生效。历史中不存在于当前候选的名称不参与菜单排序。
- 只有属性名称提交后 Metadata Cache 确认该名称已新增到目标笔记时，才把其精确字符串移到 MRU 首位。hover、键盘浏览、取消、失败和未确认编辑不计入；历史最多保存 100 个名称，不保存时间戳。

- 最近使用记录保存在当前 Vault、当前设备的 Obsidian local storage 中，与 `data.json` 分离且不同步。读取失败或记录损坏时，就按“没有历史记录”处理，不影响 Obsidian 原生候选。名称和最近使用排序不会为了排序遍历 Vault；笔记数排序只在实际需要时读取缓存元数据。
- 设置页与原生候选菜单必须共享同一排序语义。
- 键盘导航按最终可见 DOM 顺序处理方向键、Home/End、PageUp/PageDown、macOS/iOS Ctrl+P/N 和 Enter。
- 全部候选隐藏时不得提交隐藏项；焦点离开属性名编辑器后不再接管键盘。
- 无法识别 Properties 菜单或同步宿主选择状态时恢复原生顺序、可见性和交互。

## 属性值候选

- 默认关闭，并与属性名称候选相互独立。
- 每个精确属性 key 只有一个生效行为。未单独配置的 key 使用全局默认，可选 `native`、`name`、已确认选择 `frequency`、Markdown `note-count` 或 `none`；某个精确 key 也可单独设为 `custom`。同一个 key 不得同时在多个行为分组中生效。
- 设置页既可手动输入 key，也可从“缓存顶层 frontmatter 中已发现的 key + 插件已经配置的 key”的并集中选择。已经属于其他分组的 key 仍显示当前归属；移动前要求确认，确认后一次性移除旧归属并加入新归属。
- 分组胶囊可按混合语言属性名称或“最近加入当前分组”排序；这只是设置页显示顺序，不得改变 YAML 属性顺序或候选值顺序。
- 选择次数属于当前 Vault、当前设备状态，与 `data.json` 分离；只有一次候选激活随后由 Metadata Cache 确认该值已写入目标属性时才增加。hover、导航、取消、失败、同步写入或无关 metadata 变化都不计数。清除次数不得修改笔记或预设候选。
- 笔记数表示缓存 Markdown 笔记中当前属性包含该精确值的笔记数量，同一笔记只计一次；它与选择次数严格区分，并只在需要时通过 Metadata Cache 惰性读取。
- `custom` 使用置顶、普通、置底三段。置顶和置底内部顺序由用户明确指定；普通段合并原生/缓存候选与保留的预设候选，并可按原生、名称、选择次数或笔记数排序。
- 只要一个值被明确配置到置顶、普通或置底，它就成为该属性的预设候选，即使当前没有任何笔记包含它也继续可选。把预设值拖回普通段只取消固定位置，不删除其预设身份；“移除预设”只修改插件配置，不得删除笔记中的已有值。
- Obsidian 显示可识别的原生属性值弹窗时，自定义预设值加入该弹窗，原生节点继续保持宿主提交行为；没有原生弹窗时，自定义行为可在当前属性值编辑器旁显示插件自有回退弹窗。选择预设值仍通过原生属性编辑器输入路径提交，不直接写 frontmatter。
- `none` 抑制候选但保留手动输入；关闭增强或卸载插件时恢复原生弹窗状态并移除插件自有回退弹窗。
- 设置 schema 6 只自动迁移 schema 5 中可无损表达的精确、非 recent 行为覆盖。旧 recent、通配符、置顶、置底或隐藏规则若转换会改变含义，则继续原样保留并明确标记为待迁移；用户确认前仍以旧运行时行为为准。

## 设置

- 设置当前使用 schema 7；未知或非法值归一化，旧版本逐步迁移。schema 6 到 7 新增属性键候选的可选类型分组，并默认关闭以保持旧行为。属性值候选分组模型要求每个精确属性键至多有一个生效行为；无法无损转换的旧规则必须保留明确的待迁移状态，不得静默改义。
- 所有受支持的 Obsidian 版本都显示 General、Value order、Key suggestions、Value suggestions 四个设置页签，修改后立即生效。插件继续使用自己的设置界面，以保证不同宿主版本中的布局和行为一致。
- Value suggestions 展示五种可作为默认值的行为和精确 key 的 Custom 分组；普通分组用可移除属性胶囊，自定义分组用左侧属性列表加右侧置顶/普通/置底候选编辑器。设置页胶囊显示顺序可在按属性名称与最近加入之间切换；选择次数统计提供独立清除入口。
- 设置保存失败时保留内存状态，显示本地化 Notice、可访问的未保存提示和重试入口。每次保存前以及 Obsidian 报告外部设置变更时执行三方合并：外部修改且当前界面未修改的键与未来 schema 未知字段必须保留，当前界面修改过的键优先。插件替换前后的存储操作必须保持有序，已卸载实例不得启动新保存。
- Key suggestions 提供“清除最近使用历史”入口；清除会取消待确认项，只删除当前 Vault、当前设备的 MRU，不修改 `data.json`、笔记或其他 Vault。设备本地删除失败时，内存历史仍保持清空，并提示用户旧的已保存历史可能在重启后恢复。
- Key suggestions 提供临时的“测试属性名称规则”输入：同时显示首个命中的隐藏、置顶和置底规则，并按“隐藏 > 置顶 > 置底”解释最终结果。测试值不持久化，不修改 `data.json`、MRU 或笔记，也不遍历 Vault。
- 跨属性拖拽默认开启并可独立关闭；关闭上层的值拖拽功能时必须保留该偏好，以便重新开启后恢复。属性键候选增强也可独立关闭并完整恢复宿主状态。

## 明确非目标与限制

- 不支持嵌套列表、对象列表、多行 flow sequence、源码模式拖拽或跨文件移动。
- 强制把 block list 转成 flow list 时，允许丢弃只有 block 形式能表达的项目注释和空行。
- 移动端在 Obsidian 原生“编辑 / 从列表中移除 / 复制”菜单中追加重排操作，不替换原生菜单；无法取得宿主共享菜单时不做修改并保留原生行为。
- 属性值重排只支持指针输入，不提供键盘直接重排命令；拖拽状态播报只描述指针拖拽，不提供键盘重排交互。
- 插件不会只为恢复磁盘特定换行而在 Obsidian editor transaction 后追加一次不可撤销的 Vault 写入。
- 属性键候选增强依赖可识别的 Obsidian DOM 结构；如果宿主结构变化到无法安全识别，插件应停止增强并保留原生候选行为。
- 插件只处理 Obsidian 实际暴露为 Properties 的笔记；宿主不呈现 Properties 的 CR-only 文档不承诺真实 UI 写回。
